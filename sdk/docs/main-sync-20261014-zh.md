# SDK 与最新 main 同步（2026-10-14）

> 本文为当时版本的验收记录；当前版本已移除 legacy 引擎及相关测试。

本轮将 SDK 默认运行内核从 main `4ae079f` 更新到
`48e82cedd993d67f2379c36fade8973db63c74e8`。包版本仍为 `0.1.1`。
同步的是前后端与 SDK 共用的执行逻辑，不是把网页工程搬进 SDK。

## 这次带来了什么

| 更新 | 通俗解释 |
| --- | --- |
| 正式项目状态 | 新任务的检查点、当前执行和 SII 实验台账使用同一套 SQLite 状态来源，避免几个文件各说各话。导出的 `state.json` 是查看用的副本，不再是新任务的调度依据。 |
| 有权限边界的状态工具 | Agent 可通过内置 MCP 查询其范围内的任务、操作和问题；只有当前获授权的管理角色能接受协调动作。模型写一段“已成功”不能代替实际 Git 或工具接收证据。 |
| Git 恢复与收尾 | 更精确地保留已完成业务和未完成收尾；push/PR 结果不确定时，保留原操作身份与实际观测，不盲目重复写入，也不因恢复而重做已完成任务。 |
| 原生工具回执与会话 | 保留流式工具参数和原生时间信息；停止、恢复和结果补送继续核对原 Session、调用和权限，不把“准备发送”误认为“已接收”。 |
| 运行情况与队列 | 从真实活动构建统一运行视图和队列；一个课题里有多个并行 Agent 时，不再只按课题数量描述正在执行的工作。 |
| 其他修复 | GitHub 合法仓库/分支名不再因包含 `actions` 或 `workflow` 被误拦截；补入 SQLite 读取竞争、异步调度错误传播和输入路径等相关修复。 |

默认 API、`@scienceevolve/sdk/main` 和默认 CLI 使用新内核；legacy 保持独立历史实现。
新的状态能力主要接入 Agent 的内置工具和既有运行结果，不意味着新增一套公开网页接口。

## SDK 原有能力没有取消

- Git-off：CLI 的 `--workspace` 和 API 的 `start({ workspace })` 仍直接使用指定目录。
- Git-on：仍从指定原项目开始，使用已有隔离目录策略，完成后安全交付回原目录；遇到用户同期修改时报告冲突，不强行覆盖。
- 部署侧 native Codex profile、Hermes、原始输入文件、凭据解析和 SII 宿主生命周期继续保留。
- 不批量改写科研 example，不将它们强制改成 Git 协作组。

SDK 的 41 项宿主适配已按新 main 重新核对，登记为可反向还原的精确补丁。
来源清单包含 247 项运行源码、资源和回归测试文件，运行版本为：

```text
48e82cedd993d67f2379c36fade8973db63c74e8+f3c0775e4f8b06de
```

SII 启动顺序也与 main 对齐：先打开正式状态库并绑定台账，再恢复运行引擎，最后启动监控。
关闭时仍等待任务和已接受的写入安全收尾。

### 同步时发现的 Windows 兼容问题

首次完整回归没有通过，发现了以下问题并进行了适配：

- 验收记录对目录执行 `fsync`，Windows 返回 `EPERM`。改用已存在的跨平台目录同步函数；记录文件本身仍先写入并刷盘，未吞掉文件写入错误。
- 原会话恢复按完整 Unix 权限位校验文件，Windows 的权限表示不同，误报输入不匹配。Windows 保留可写位校验，Unix 继续检查完整权限；原文件内容、类型和链接数仍严格核对。
- R04 故障验收依赖 Linux 的 `/proc/self/fd`。非 Linux 平台改为读取前后核对路径与已打开文件的设备号、文件号和单链接身份，保留内容校验；Linux 继续检查描述符路径。该变化属于验收控制器，不是放宽 Agent 文件工具的权限。

测试层还补齐了 SDK 路径、Windows 命名管道、文件 URL、官方事件样本和 Hermes 预期。
Windows 的 Git 集成测试改为单测试文件运行，并使用有限的较长测试时限；实际模型请求与运行恢复的时限没有改变。
无文件符号链接权限的案例会明确跳过，不算通过。原本仅适用于 Linux `/proc` 的原始进程测试，以及 Windows 未实现的 Unix Inspire shell 包装器测试，也不计作 Windows 验收。

## 没有同步的部分

网页组件、HTTP 路由、交互式项目助手和配置推荐服务不进入 SDK-only。
它们留在 main；共用的运行内核、状态和 Git 机制已同步。
没有升级或重启已有科研实验。

三处失败的处理与边界：

1. **Git 测试夹具错误。** 临时测试仓库的换行配置被错误地交给生产 Git 命令执行器，触发其配置白名单保护。改由夹具直接配置自己的临时仓库；生产白名单没有放宽。
2. **SII 测试等待过短。** 默认约 1 秒的轮询未等到真实状态文件。测试改为最多 10 秒，同时显式检查逻辑调用异常，避免用更长等待掩盖错误；完整生命周期回归通过。生产超时没有改变。
3. **两次 Git 收尾调用超时。** 同一测试隔离复测在 67.7 秒内通过，没有修改收尾逻辑或进一步放宽其时限。完整回归中的超时根因尚未确定，仍需保留 Windows 耗时波动风险，不能写成已修复一个确定的运行时 bug。

**本轮结论是“完整回归有失败记录，失败用例复测与相关回归通过”，不是重新执行了一次全量零失败回归。**
原始 JSON 位于本地同步工作树的 `temp-sync-20261014/`：
`sdk-final-results.json`、`sdk-final-retries.json` 和 `sdk-final-critical-regression.json`。
临时诊断目录不作为 SDK 交付内容。

这些是本地软件验证，不是新的真实模型、真实 GitHub 写入或科研成功验收。
Linux/macOS 及完整 Harness 实机矩阵本轮未执行。

MCP 依赖最低版本与 main 对齐为 `^1.30.1`，锁文件解析为 `1.32.1`；独立安装包验收也使用 `1.32.1`。
没有更新现有共享的 `node_modules`，避免影响冻结的实验与其他 SDK 工作树。
本地长回归使用原安装环境的 MCP `1.30.0`，该结果与新依赖的独立安装包验收分开记录。

本轮 `npm audit` 返回 9 项告警（3 moderate、3 high、3 critical）。涉及 Pi、Vitest 及传递依赖；
其中部分修复需要跨大版本升级。本轮没有执行 `audit fix --force`，也不将构建通过视作安全审计通过。
这些依赖风险需要另做升级与兼容性验收。

## 更新后怎么使用

源码更新后执行 `npm run build`。独立安装用户需重新打包、安装 `.tgz`；原来的安装包不会自行变化。
调用方式不变，启动新实验时使用新的独立 `dataDir`。

已有实验继续使用它们原来的 SDK 快照和 `dataDir`。
本轮更新了状态协议和运行版本，不能直接用新二进制恢复旧目录，也不能手改版本标记绕过保护。
如果需要迁移运行中的任务，应另做显式迁移与恢复验收；本轮没有执行这种迁移。

## 部署边界

这次源码同步不自动替换已安装的全局 CLI，不自动启动新版网页服务，也不改写已有工作树中的未提交修改。
科研实验继续使用各自固定的 SDK 快照；升级源码与迁移旧任务是两个独立动作。
